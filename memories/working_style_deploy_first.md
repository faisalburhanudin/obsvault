For new personal/side projects, the user prefers to deploy a working POC on day one — even if it's broken or minimal — and iterate the next day, rather than building it out fully before shipping.

**Why:** they've done this before (e.g. an alphabet app built for their kids) and found that having something already deployed makes the problem "less abstract" — concrete feedback from a live thing beats planning in the abstract.

**How to apply:** when scoping a new build (e.g. [[Asset Inventory]] hydroponic + local AI POC), default to "smallest thing deployable today" over "properly scoped MVP." Don't propose a multi-step build-then-deploy plan unless the user asks for one — bias toward get-it-live-first, refine-in-place.
